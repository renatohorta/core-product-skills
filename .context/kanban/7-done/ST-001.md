# ST-001 — cp-operation-pentest v1 — code security audit

## User story
As a team maintaining our own polyglot codebase, we want a defensive, white-box security audit skill that finds vulnerability classes in our source and feeds each confirmed hole into the pipeline as a BUG, so holes are fixed through the flow we already use.

## Acceptance criteria
- **ST-001/AC-1**: Running the skill in a project prints a work packet listing the vulnerability classes, their references, and the discovered source surface; it audits the project folder it runs in by default and `--path` narrows to a subtree.
- **ST-001/AC-2**: `--record FILE|-` validates the assessment document (each `## Finding` has Class, Location, Evidence, Verdict, Severity) and creates one `BUG-NNN` per confirmed finding; a killed or "Cannot verify" verdict creates no card.
- **ST-001/AC-3**: Coverage is tracked per `(module × vulnerability-class)` pair, cumulative across `--record` runs; `--record` exits 1 while any pair in the surface is never audited and not waived.
- **ST-001/AC-4**: `--waive PATH|GLOB --reason "..."` records a coverage waiver with a reason of at least 12 characters.
- **ST-001/AC-5**: The cp-orchestrator routing packet includes a route to cp-operation-pentest and the `cp-operation-*` family is registered for routing.
- **ST-001/AC-6**: SKILL.md passes the skill contract (description opens with "Use when", closing frontmatter, exit codes documented, under 20 KB); the ported BugHunter patterns, the 7-Question Gate and evidence hygiene live in references/ with attribution.
- **ST-001/AC-7**: The pentest has its own profile.json with polyglot source_extensions driving the closure surface.

## Definition of Done
All acceptance criteria met, pure stdlib under `python -S`, the full pytest suite green, BugHunter attribution recorded in NOTICE/credits, and the design initiative moved to processed.
