# ST-002 — cp-ui v1 — design system, UI audit, verify

## User story
As the operator of a product built through the cp-* pipeline, I want a design system chosen and recorded before code and a UI audit after code, so the product has its own identity and its UI bugs are found, fixed and re-checked through the flow we already use.

## Acceptance criteria
- **ST-002/AC-1**: A design system is proposed as 2-3 distinct accessible directions with previews, chosen by a named operator, and recorded as MASTER.md + tokens.json with who chose it and why; replacing it needs --force and a reason.
- **ST-002/AC-2**: The audit has three layers (static candidates, optional visual audit, evidence checklist) and its report header states honestly what was and was not verified; the visual command runs only with explicit --visual.
- **ST-002/AC-3**: Each confirmed finding opens one BUG per rule and file (occurrences listed, deduplicated against open BUGs, a regression opens a new one); dismissed candidates persist with a reason.
- **ST-002/AC-4**: A UI BUG opened by cp-ui is closed by cp-ui --audit --verify BUG-NNN, which cannot pass vacuously, and cp-build --finish accepts that record instead of a regression test.
- **ST-002/AC-5**: cp-build, cp-review, cp-analysis-design and cp-orchestrator hand the design system / audit to the agent and route UI requests to cp-ui.
- **ST-002/AC-6**: The skill is stdlib-only under python -S, ships the vendored UUPM with its license, passes the skill contract, and is documented in ADR-0022, CLAUDE.md and the README.

## Definition of Done
All acceptance criteria met, the full pytest suite green, ADR-0022 recorded, NOTICE entry for UUPM, the design initiative moved to processed.
